# Архитектура

## 1. Почему именно так

Задача звучит как «дать зрителям звук выбранных приложений, не трогая ничего вокруг». Разберём
варианты, которые были изучены, прежде чем выбрана реализация.

| Подход | Итог |
|---|---|
| Взять системный звук (`getDisplayMedia`/desktopCapturer) и вырезать лишнее | невозможно: после микширования отдельные приложения неотделимы |
| Виртуальное устройство + переадресация приложений | запрещено условиями задачи |
| Готовые виртуальные кабели (VB-Cable, Voicemeeter, VAC) | то же, плюс требуют установки стороннего ПО |
| Микрофонная «дорожка» через виртуальный микрофон (как делают Linux-решения с venmic) | требует виртуального устройства; на Windows такого публичного пути нет |
| Захват каждого процесса через WASAPI process loopback и собственный микшер | **выбрано** — ничего не устанавливает, не меняет устройства, работает на уровне процессов |
| Отправка микса в трансляцию через подмену звуковой дорожки `getDisplayMedia` | **выбрано** — дорожка живёт внутри рендерера, никаких устройств не появляется |

Итог: звук вообще не проходит через аудиоустройства. Плагин читает потоки процессов и отдаёт
получившийся PCM прямо в тот `MediaStream`, который Discord отправляет зрителям.

## 3. Слои и их контракты

### C++ (`native/src`)

| Файл | Ответственность |
|---|---|
| `dsp/audio_format.h`, `dsp/convert.{h,cc}` | описание формата, декодирование u8/s16/s24/s32/f32, даунмикс в стерео |
| `dsp/ring_buffer.{h,cc}` | потокобезопасный FIFO кадров с подсчётом потерянных кадров |
| `dsp/resampler.{h,cc}` | sinc-ресемплер (Blackman, cutoff 0.95·min(1, out/in)), 44.1↔48↔96 кГц |
| `dsp/mixer.{h,cc}` | сведение N источников, плавное включение/выключение (20 мс), лимитер |
| `capture.h` | интерфейсы `IAppEnumerator`, `ICaptureSource`, `ICaptureFactory` — шов между движком и ОС |
| `app_identity.{h,cc}` | группировка сессий в приложения, ключ `exe:<путь>` |
| `engine.{h,cc}` | правила, поток захвата, поток микширования, применение плана, статистика |
| `platform.{h,cc}` | выбор бэкенда (`auto`/`wasapi`/`mock`), `probeSupport()` |
| `mock/mock_backend.{h,cc}` | тестовый бэкенд: программируемый список приложений + генератор сигнала |
| `win/session_watcher.cc` | перечисление сессий по всем render-устройствам, события о новых сессиях, метры уровня |
| `win/process_loopback.cc` | `ActivateAudioInterfaceAsync` + захват процесса и его дерева |
| `win/windows_util.cc` | строки UTF-8/UTF-16, HRESULT → текст, версия ОС, таблица процессов, ресурсы версии |
| `addon.cc` | N-API: JSON-строки наружу, PCM как Buffer, единая точка входа для JS |
| `json.h` | минимальный JSON-писатель (без зависимостей) |

### TypeScript (плагин)

| Файл | Ответственность |
|---|---|
| `native.ts` (main) | поиск и загрузка `.node`, `probe`, значки приложений через Electron, тестовый сценарий |
| `nativeBridge.ts` | типизированная обёртка над `VencordNative`, нормализация пиков 0..1000 → 0..1 |
| `apps/rules.ts` | режимы, правила, список приложений, сортировка — чистые функции с тестами |
| `apps/store.ts` | единое состояние: окружение, правила, список, статистика, статус трансляции; опрос только пока открыта панель или идёт трансляция |
| `stream/intercept.ts` | подмена звуковой дорожки демонстрации, контроль «Discord сам не просил звук» |
| `audio/sourceTrack.ts` | планирование PCM по Web Audio в непрерывную дорожку, подсчёт недоборов/потерь |
| `ui/*`, `components/*` | панели и строки приложений |
| `index.tsx` | описание плагина: настройки, патч кнопки у микрофона, flux, toolbox, запуск/остановка |

## 4. Ключевые решения

### Один непрерывный поток вместо перезапуска

Требование «менять состав на лету» решено так: движок всегда микширует **один** поток в **один**
кольцевой буфер, а изменения состава применяются как добавление/удаление источников внутри микса.
Выключение приложения — это плавное затухание за 20 мс и удаление источника, а не перезапуск
демонстрации. Лимитер и затухание исключают щелчки, а отсутствие пересоздания потока — разрыв
видео и переподключение голосового канала.

### Задержка и устойчивость

* захват запрашивается в формате 48 кГц stereo float32 с `AUTOCONVERTPCM | SRC_DEFAULT_QUALITY`;
  если драйвер отказывает — берётся микс-формат устройства и конвертируется внутри (декодер +
  sinc-ресемплер);
* суммы буферов: 200 мс у WASAPI-клиента, 250 мс на приложение, 500 мс на выходе движка,
  30–180 мс в рендерере (настройка «запас звукового буфера», по умолчанию 60 мс);
* недоборы и переполнения считаются и показываются, а не проглатываются.

### Шлюз захвата

Движок знает, идёт ли трансляция (`RuleSet::active`). Пока трансляции нет, работает только
наблюдение за списком приложений: ни один аудиоклиент не активируется, звук не читается. Это
исключает фоновую нагрузку и любые «особые» взаимодействия со звуком вне трансляции.

### Опрос вместо постоянного сканирования

Перечисление сессий живёт в отдельном потоке с MTA, подписывается на
`IAudioSessionNotification` (событие о новых сессиях) и просыпается раз в секунду для сверки.
Изменения наружу отдаются флагом «что-то изменилось»; список перечисляется один раз на изменение.
Рендерер опрашивает движок раз в секунду и только когда открыта панель или идёт трансляция; через
30 секунд после закрытия последней панели движок останавливается.

### Идентичность приложений

Ключ приложения — `exe:<нормализованный путь>`. Путь берётся из процесса сессии
(`QueryFullProcessImageNameW` с `PROCESS_QUERY_LIMITED_INFORMATION`, прав администратора не
требуется). Для UWP-приложений, где путь недоступен, используется Application User Model ID
(`GetApplicationUserModelId`), а если и его нет — процесс считается несохраняемым («не сохраняется»
в интерфейсе). Несколько процессов одного пути объединяются в одну строку, и в захват попадают
только корневые процессы группы (дети попадают в дерево), поэтому звук не суммируется дважды.

### Почему рендерер, а не main-процесс

Звук для трансляции Discord берёт из рендерера. Поэтому модуль возвращает PCM в JS, а дорожку
собирает Web Audio внутри рендерера: никакого дополнительного IPC на каждый буфер между процессами
не нужно, а `MediaStreamTrack` создаётся там, где его ждёт Discord.

### Что происходит, когда Discord не просит звук

Если в интерфейсе выключено «Передавать звук», Discord вызывает захват без аудио-параметров.
Плагин в этом случае **не** добавляет звуковую дорожку и пишет в панель, что передача звука
выключена в Discord: включать её за пользователя он не имеет права.
