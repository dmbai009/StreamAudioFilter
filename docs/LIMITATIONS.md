# Ограничения и проверка поддержки

Этот документ отвечает на главный вопрос: **можно ли вообще передавать зрителям звук только части
приложений, не создавая виртуальных устройств и не меняя системные настройки.** Ответ: да, но не на
всех версиях Windows — и это ограничение нельзя обойти «маршрутизацией», о которой просили не
умалчивать.

## 1. Что умеет Windows

Захват звука отдельного процесса реализован в Windows через **WASAPI process loopback**:
`ActivateAudioInterfaceAsync` с `AUDIOCLIENT_ACTIVATION_TYPE_PROCESS_LOOPBACK` и
`PROCESS_LOOPBACK_MODE_INCLUDE_TARGET_PROCESS_TREE`.

* Microsoft: `AUDIOCLIENT_ACTIVATION_TYPE_PROCESS_LOOPBACK` — «Minimum supported client: Windows 10
  Build 20348»
  (<https://learn.microsoft.com/en-us/windows/win32/api/audioclientactivationparams/ne-audioclientactivationparams-audioclient_activation_type>);
* тот же порог указан для `IAudioClient` при активации с `AUDIOCLIENT_ACTIVATION_PARAMS`
  (<https://learn.microsoft.com/en-us/windows/win32/api/mmdeviceapi/nf-mmdeviceapi-immdevice-activate>);
* официальный пример Microsoft `ApplicationLoopback` построен ровно на этом механизме
  (<https://learn.microsoft.com/en-us/samples/microsoft/windows-classic-samples/applicationloopbackaudio-sample/>).

Ключевое свойство: захват **не привязан к аудиоустройству**. Не нужно ни знать, куда играет
приложение, ни перенаправлять его звук. Это и есть причина, по которой требование «не трогать
устройства и системный звук» выполнимо.

### Сборка Windows

| Сборка | Версия | Process loopback |
|---|---|---|
| 19041–19045 | Windows 10 2004–22H2 | **нет** |
| 20348 | Windows Server 2022 (тот же код, что в новых 10/11) | есть |
| 22000+ | Windows 11 | есть |

Проверить свою сборку одной командой (PowerShell):

```powershell
[System.Environment]::OSVersion.Version.Build
```

или

```powershell
Get-ItemProperty 'HKLM:\SOFTWARE\Microsoft\Windows NT\CurrentVersion' |
    Select-Object ProductName, DisplayVersion, CurrentBuildNumber
```

Плагин делает ту же проверку сам и вдобавок **выполняет реальную попытку активации**: кнопка
«Проверить поддержку» в разделе «Диагностика» запускает настоящий `ProcessLoopbackCapture` и
печатает либо успех, либо `HRESULT` с расшифровкой (`AUDCLNT_E_*`, `E_INVALIDARG`, `E_NOTIMPL` и
т.д.). Догадка «наверное, не поддерживается» не используется: если система умеет — вы это увидите,
если не умеет — увидите код ошибки.

## 2. Что происходит на Windows 10 сборки < 20348

Ничего не подменяется и не «объезжается»: фильтрация по приложениям невозможна, потому что нужного
API в системе нет. Плагин:

* показывает в панели причину с точной сборкой и требуемым порогом;
* не включает никакие обходные пути (не создаёт виртуальные устройства, не перенаправляет звук
  приложений, не меняет настройки Discord);
* оставляет трансляцию ровно такой, какой её сделал Discord. Если фильтрация не применена, а
  трансляция идёт, панель прямо пишет «фильтрация не применена», а не делает вид, что работает.

Отдельно проверенный и отклонённый путь (чтобы не возвращаться к нему):

| Вариант | Почему не используется |
|---|---|
| Захват всего системного микса + вырезание ненужного (EQ/вычитание) | вырезать произвольный набор приложений из уже смешанного звука математически невозможно |
| Виртуальное устройство + переадресация приложений | запрещено условиями задачи (пункты 3–5) |
| Mute/volume через `ISimpleAudioVolume` на время трансляции | меняет то, что слышит сам пользователь, и не даёт зрителям отдельный микс |
| Запись «что слышно» с устройства (loopback) с фильтрацией по приложению | API фильтрации по процессу у обычного loopback отсутствует до 20348 |
| Перехват через виртуальный драйвер (APO) | требует установки драйвера, подписи и прав администратора |

## 3. Совместимость с Voicemeeter, VB-Cable и другими виртуальными микшерами

Отдельный пункт, потому что для многих пользователей Discord давно работает через Voicemeeter, и
очевидный вопрос — не сломается ли фильтрация из-за того, что «звук идёт не туда».

Не сломается, и вот почему:

* **Захват следует за процессом, а не за устройством.** Приложению безразлично, что его вывод идёт
  в `Voicemeeter Input (VB-Audio Voicemeeter VAIO)`, в USB-гарнитуру или в HDMI: process loopback
  перехватывает поток процесса независимо от конечной точки.
* В нашем перечислении сессий участвуют **все** активные render-устройства, а не только устройство
  по умолчанию (`IMMDeviceEnumerator::EnumAudioEndpoints(eRender, DEVICE_STATE_ACTIVE)`), поэтому
  приложения, ушедшие на VAIO/кабель, всё равно видны в списке.
* Никакие устройства не выбираются и не переключаются: работать можно одновременно с Voicemeeter
  для микрофона и обычным выводом для приложений, плагин ничего не «займёт» и не переведёт.

Ограничения, о которых стоит знать:

* Если **само приложение-микшер** (например, `voicemeeter.exe` воспроизводит что-то в мониторы)
  выдаёт звук, оно появляется в списке как обычное приложение и фильтруется как любое другое.
  Пропускать звук «через» него к зрителям нельзя — мы перехватываем источники, а не промежуточные
  микшеры.
* Если игра выводит звук в VAIO и вы слушаете его через Voicemeeter, а в трансляцию хотите именно
  **микс Voicemeeter** (то, что слышите вы, но без, например, Telegram), — это уже не задача
  «выбрать приложения»: микс Voicemeeter неотличим от одного источника. Фильтровать нужно сами
  приложения-источники, а не микшер.
* ASIO-приложения и приложения, использующие эксклюзивный режим, в списке могут не появиться:
  WASAPI-сессия для них не создаётся. Это видно в панели как отсутствие приложения — с подсказкой
  «запустите воспроизведение и обновите список».

## 4. Другие технические ограничения плагина

| Ограничение | Причина и что с этим делать |
|---|---|
| Одновременно захватывается ограниченное число приложений (по умолчанию 12, настраивается до 32) | каждый захват — отдельный аудиоклиент; при превышении лимита появляется предупреждение «часть звука не передаётся», а не тихая потеря |
| Захват возможен только для приложений, создающих звуковую сессию | системные звуки (уведомления) — отдельная псевдо-сессия «Звуки системы», её можно фильтровать целиком |
| Ресемплирование 44.1↔48 кГц и переход 48→96 кГц выполняются в плагине | системы с другим форматом устройства не поддерживаются «как есть», поэтому формат приводится к 48 кГц f32 внутри (SNR > 70 дБ, см. `docs/TESTPLAN.md`) |
| Плавающая панель — окно внутри Discord | если вы демонстрируете весь монитор, окно Discord может попасть в кадр. Поэтому панель сворачивается при трансляции (настройка), а попадание интерфейса в кадр — это поведение Discord, а не плагина |
| Кнопки внутри окна запуска трансляции нет | у этого окна нет публичного API; подробности и альтернатива — в `docs/UI.md` |
| Правила для приложений без доступного пути к файлу (некоторые UWP/защищённые процессы) не сохраняются между запусками | идентификатор процесса не годится для долгого хранения (переиспользуется). Такие строки помечаются значком «не сохраняется» |
